Design manual: Nocturne for StellarServerForge

The single source of truth for the visual overhaul of the Swing desktop app. Every value here is normative. Where this document and existing code disagree, this document wins.

0. Scope and ground rules

  • This is a visual and interaction overhaul only. Do not change server logic, Java resolution, modloader installation, UPnP, or process management behaviour.
  • The previously discussed “galaxy / starfield / nebula” direction is cancelled. Remove starfield backgrounds, nebula glows, gradient floods, cyan/gold accents, drop-shadow text and any decorative animation.
  • The system is Nocturne: a near-neutral blue-grey dark ground, Inter at weight 400/500, 8px radii, and a single blurple accent used as a line, mark or glow — never as a large fill.
  • No hard-coded colors, fonts, sizes or paddings anywhere in UI code. All of them come from one theme class (§2).
  • No emoji in the UI. Icons are Phosphor SVGs (§8).

1. Technical approach

Swing's default look-and-feel cannot express this system. Adopt FlatLaf (com.formdev:flatlaf, plus flatlaf-extras for SVG icon support) and drive it from a properties file rather than per-component styling.

  1. Add flatlaf + flatlaf-extras to the build; keep them inside the shaded JAR and the jpackage image.
  2. Create NocturneTheme extends FlatDarkLaf backed by resources/themes/Nocturne.properties (§2). Install it once, before any window is constructed, on the EDT.
  3. Bundle Inter (Regular, Medium, SemiBold) and JetBrains Mono (Regular) as TTFs in resources; register them with GraphicsEnvironment.registerFont at startup and set defaultFont in the properties. Do not rely on the system having Inter.
  4. Introduce a single Tokens class exposing the values in §3–§5 as static finals (Tokens.BG, Tokens.SPACE_6, …). Every layout reads from it.
  5. Layout with MigLayout or GridBagLayout. Remove all setBounds/null-layout code and all absolute pixel positioning.

Status colors — a deliberate extension

Nocturne is mono and carries no semantic error/warning role, but server lifecycle states need one. Add exactly these three, derived at the accent's own lightness and chroma so they carry equal visual weight: running #84d9a0, warning #d9c184, failed #d98a84. Idle uses neutral-500 #9397ab. Use them only as an 8px dot, a 1px border, or small-caps label text — never as a panel fill. Add no further colors.

4. Type

Inter throughout, with JetBrains Mono reserved for the console, log output, paths, versions and port numbers. Hierarchy is size and space; never bolden a heading past 500.

5. Spacing, radius, elevation

The scale is intentionally dense (0.7× density). Round the tokens to whole pixels in Java: 3, 6, 8, 11, 17, 22. Use nothing between them.

  • Window edge padding: 22px. Card interior padding: 17px. Gap between cards: 17px. Gap between a label and its field: 6px. Gap between stacked fields: 11px. Gap between sibling buttons: 8px.
  • Radius: 4px for tags and dots, 8px for buttons, fields and small cards, 14px for the large panel containers and dialogs.
  • Elevation on a dark ground is an edge plus ambient darkness, not a stacked shadow. Level 1: 1px #3f424d border, no shadow. Level 2: 1px #595d6c border + a soft 18px black-55% drop. Level 3 (dialogs only): 1px #9397ab border + 40px black-65% drop. Never stack more.

6. Component specifications

Buttons

All buttons are outlined on a transparent ground. There is no solid-filled button in this system.

  • Primary (Launch, Continue, Save): 1px accent #9184d9 border, accent-300 text, transparent fill. One per screen region.
  • Secondary: 1px neutral-700 #595d6c border, primary text.
  • Ghost (Back, Cancel): no border, neutral-400 text, hover tints the background to accent-900.
  • Destructive (Stop server, Purge cache): 1px #d98a84 border, same text color. Not filled.
  • Height 34px, horizontal padding 14px, 8px radius, label at body size weight 400. Icon-plus-label buttons put a 14px icon after the label with a 6px gap.
Cards

Surface-filled rounded containers: #232532 fill, 14px radius, level-1 or level-2 edge, 17px interior padding. Internal order is always kicker → title → body → meta row of tags. Every content region on every screen sits in a card; nothing floats on the raw window ground except the header bar and the screen title.

Fields and choices
  • Text field / combo: fill #1c1e2c, 1px neutral-800 border, 8px radius, 32px height, 10px horizontal padding. Focus swaps the border to accent and draws the 2px focus ring.
  • Label above the field in Kicker style; optional helper Caption below.
  • Mutually exclusive short choices (Java mode, modloader type) use a segmented control: a single 8px-radius neutral-800-bordered strip of equal-width options; the selected option gets an accent-900 fill and accent-300 text. Not radio buttons, not a dropdown.
  • RAM allocation is a slider with a mono numeric readout to its right, snapping to 1 GB steps, plus a caption naming the machine's detected total RAM.
Tags

Small 4px-radius labels, 10px/600 uppercase text, 3px/8px padding. Accent variant: accent-900 fill, accent-300 text. Neutral variant: neutral-900 fill, neutral-300 text. Outline variant: 1px neutral-700 border, no fill. Status tags prefix an 8px status dot.

Header bar

A single 52px row across the top: wordmark “StellarServerForge” at 15px/500 on the far left, then the section links (Mission Control, Mods, Utilities, Settings) as ghost-styled text at body size, then the live status tag pushed to the far right. The active section is marked by a 2px accent underline, not a fill. This bar replaces any existing tab strip or menu-driven navigation.

Console

A level-1 card with no interior padding on the text area itself — the scroll pane fills the card and carries 17px inset padding. Ground #292b31, mono 12px, line-height 1.6, neutral-100 text. Color only three things: server-lifecycle lines (Starting/Done/Stopping) in accent-300, warnings in #d9c184, errors and stack traces in #d98a84. Everything else stays neutral-100 — do not colorize timestamps or thread names. Auto-scroll to tail with a pause-on-manual-scroll behaviour, and a command input row pinned below the pane with an accent-300 > prefix.

7. Interaction states

Every interactive element must implement all five. No browser or Swing defaults survive.

StateTreatment
HoverBackground tints to accent-900 #2b2741; an outlined element also lifts its border one step toward accent-400.
PressedAccent-800 #423a6a fill, text to accent-200. No motion, no scale.
Keyboard focus2px accent ring at 2px offset, on every focusable control including the console and the slider.
Disabled45% opacity, no hover, no pointer feedback. Launch is disabled while running; Stop is disabled while idle.
BusyAn indeterminate 2px accent progress line pinned to the bottom edge of the card doing the work, plus the button's label swapping to a present participle (“Installing…”). No spinners, no modal blocking.

8. Icons

Phosphor Icons (phosphoricons.com), Regular weight only, rendered as SVG through FlatSVGIcon — not an icon font, not PNG. 16px in buttons and rows, 20px in headers, colored by currentColor mapping so they inherit their container's text color. Suggested mapping: Launch → play, Stop → stop, Settings → gear-six, Mods → puzzle-piece, Utilities → wrench, Console → terminal-window, Import → download-simple, Folder → folder-open, Warning → warning, Network → globe-simple. No other icon sources.

9. Screen-by-screen direction

Layouts are left-aligned and asymmetric: content hugs the left edge and whitespace collects on the right. Minimum window 1100×740; everything must reflow, not clip, down to that.

Mission Control

Header bar, then a two-column split (roughly 1.3 : 1). Left card: the working directory as a mono path in the title position, then a three-column grid of six labelled facts — Minecraft version, modloader + version, Java version + mode, RAM, port, Java mode — each a Kicker label over a mono value. Below the grid, the primary Launch button and a secondary “Re-run setup wizard”. Right card: the live status — status tag, one-line plain-language status sentence, one line of context (last exit, uptime, or crash count), and the auto-restart state as a tag. Nothing else on this screen; resist adding charts, activity feeds or player counts.

Setup wizard

Five steps: Minecraft version → modloader type → modloader version → Java version → RAM. A single row of five step tags at the top, the current one in the accent variant and the rest outlined; no progress bar. One card, max 640px wide, left-aligned on the window — do not center it. Each step shows exactly one decision, its input, and at most two supporting tags (detected latest release, auto-recommended Java version). Footer row: ghost Back on the left, primary Continue on the right, Back disabled on step 1 and Continue relabelled “Install” on step 5. Validation errors appear as a Caption in #d98a84 under the offending field, never as a modal dialog.

Server detail & console

A control row (status tag + mono uptime on the left, Launch and Stop on the right), then the console card taking all remaining vertical space, then a two-column row of two short cards: the auto-restart toggle with its 5-attempt cap named in a Caption, and crash diagnostics. The diagnostics card is the only place crash guidance appears: on a non-graceful exit it names the detected cause (Java/modloader mismatch, port in use, client-only mod on a dedicated server) as its title and one concrete remedy as its body, with a secondary button that performs that remedy where one exists. When there is no crash it reads “No crash on record” and stays quiet — do not hide the card.

Settings

Two columns of cards. Left: server settings — RAM slider, port field, and “Re-enter setup wizard” as a full-width secondary button. Right: Java resolution mode as a three-option segmented control (Automatic / System PATH / Force-managed) with a Caption naming the currently resolved JDK path, then a Networking group with UPnP port forwarding and the Windows Firewall rule check as label-plus-status rows, each with its own action tag or button. Settings apply on change with an inline confirmation, not via a Save/Apply footer.

Mods, Utilities, CurseForge import

All three follow one pattern: a screen title, one sentence of Caption text explaining what the screen does, then a card per operation containing the operation's title, a one-line description, and its single action button. The Mods scanner additionally lists detected client-only mods in a table (themed header, 1px row rules, no zebra striping) with a checkbox column and one “Move selected” button beneath. Destructive operations (cache purge) use the destructive button and a confirmation dialog at elevation level 3.

10. Copy conventions

  • Sentence case everywhere except Kickers and tags, which are uppercase. No title case.
  • Buttons are verbs: “Launch server”, “Stop server”, “Move selected”, “Export server pack”. Never “OK”, never “Submit”.
  • State is described in plain language, not jargon: “Idle — no process running”, not “STATE: NO_SETTINGS”. Keep the internal state names out of the UI.
  • Errors name the cause and the fix in that order, in one sentence each. No stack traces in the UI outside the console.
  • No exclamation marks, no second-person cheerfulness, no emoji.

11. Acceptance checklist

  • FlatLaf installed from Nocturne.properties before the first window is built; no Nimbus/Metal fallback path left in.
  • Inter and JetBrains Mono are bundled and registered; the app renders identically on a machine with neither installed.
  • Grep the source: zero new Color( outside Tokens, zero new Font( outside Tokens, zero setBounds.
  • No solid-filled button anywhere; no accent area larger than a tag.
  • Every focusable control shows the 2px accent focus ring; the whole app is operable by keyboard alone.
  • All five lifecycle states (first run, idle, installing, running, crashed) render correctly and are reachable in a manual pass.
  • Window resizes from 1100×740 to maximised with no clipped text and no fixed-width panel stranded mid-window.
  • No starfield, gradient flood, glow, emoji or decorative animation remains.

Anything not specified here is a decision to raise, not to invent. When in doubt, choose the option that removes an element.
